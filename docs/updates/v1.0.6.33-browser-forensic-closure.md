# v1.0.6.33 — Phase-01 + Phase-02 Browser Forensic Closure

v1.0.6.33 is a confirmed-defect hotfix against the frozen v1.0.6.32 baseline (`a001f67972c47832a5e59af5f9350a0409e7eab6`, source ZIP SHA-256 `fdc18905084f41f9418d239f5e8f0ab632fa114c05b065835dcc126d32a1664f`). It does not add a new browser engine, workflow, dependency, database schema, build system, or packaging feature.

## Confirmed defects closed

1. **Chrome preflight/launch target mismatch.** Runtime discovery now mirrors Playwright 1.61.0's Windows `chrome` channel search order and validates the first existing target instead of accepting a registry/lower-priority executable that Playwright would not launch.
2. **Installed Chrome identity trust gap.** ProductName is no longer sufficient. The selected `chrome.exe` must pass Windows Authenticode trust and resolve to publisher `Google LLC`.
3. **Installer URL path weakness.** The Google MSI policy now requires the exact approved HTTPS host/path, not merely a matching filename suffix.
4. **MSI cancellation semantics.** Windows Installer exit code 1602 is reported as user cancellation rather than generic installer failure.
5. **Installer coordinator backpressure.** Only byte-level download progress may be dropped; security/lifecycle transitions are non-droppable.
6. **Active dialog state race.** Concurrent Open Browser/Re-check requests cannot reset an active installer dialog to idle controls.
7. **Diagnostic overclaim.** Chrome-only compliance now requires measured Windows process-path equality with the trusted Chrome channel target. Requested-channel inference without process evidence is explicitly `unverified`.
8. **Documentation/source hygiene.** Current baseline/candidate wording is synchronized and the Chrome runtime EOF hygiene defect is removed.

## Preserved

- Playwright `channel="chrome"` production launch.
- No Chromium fallback or custom executable path.
- Sandbox mandatory ON and normal HTTP-cache default ON.
- Managed persistent `BrowserProfiles/slot_N` profiles.
- Workflows, licensing, Task/runtime/workspace/report schemas.
- `requirements.txt`, `requirements-build.txt`, `.github/workflows/ci.yml`, `build.py` and packaging surfaces.
