## Root Cause

The PR-04 semantic-parity test hashed `ast.dump(...)` output generated under Python 3.13. GitHub CI correctly runs the supported Python 3.12 target, whose AST serialization contains version-specific empty-field differences. The first extracted method therefore produced a different hash despite unchanged executable semantics. Static repository verification passed and the run reported 276 passing pytest tests before the single false-negative parity assertion.

## Fix

The extracted-method parity gate now uses VibraPilot's canonical semantic AST serializer (`canonical-semantic-ast-v2`), which omits empty/`None` fields before hashing. The new verification scope pins the historical PR-04 scope, canonical baseline-equivalent method hashes and frozen runtime/support hashes.
