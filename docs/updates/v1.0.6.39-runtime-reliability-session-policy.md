## Phase 1 implementation

### Workflow-scoped session policy

The Core now resolves `WorkflowTaskSchema.requires_session` as the authority. Session-required workflows retain Login Verification. Sessionless workflows do not receive Core login polling, login status mutation, or an unconditional pre-Start `ensure_session()` call.

### Background Chrome policy

Browser runtime policy is version 2. Pre-v2 settings migrate once to `background_throttling_enabled=false`. Existing Chrome anti-background timer, occluded-window and renderer switches therefore remain active by default for production automation. Users can explicitly re-enable throttling after migration.

### Windows sleep guard

`src/vibrapilot/power_management.py` owns one process-level Windows `PowerRequestSystemRequired` request while one or more Task workers are processing. Task-token ownership prevents duplicate release. No display-power request or input simulation is used.

### Deterministic active page

Startup prefers the configured target origin when available, otherwise a usable non-internal page. New tabs can become owned after navigation while the worker is idle; during processing only a workflow-related popup/opener can take ownership. Active-page closure selects a deterministic replacement. Diagnostics include page index/scheme/host/path only.

### Browser resilience

Automatic crash restart remains disabled by default. When enabled, restart is limited to idle/outcome-safe checkpoints. Planned page replacement avoids transient external-close classification. Persistent context recycle remains after finalized items and only re-verifies Core login for session-required workflows.

## Out of scope

Workflow Update/Replace, Remove/Unload/Deactivate, restart-free Activate/Switch, per-Task workflow identity and true simultaneous multiworkflow execution remain Phase 2.
