# v1.0.6.1 GitHub Actions Line-Ending Verification Fix

Date: 2026-08-08

## Problem

The Windows GitHub Actions runner checked out LF-tracked frozen design-contract text using CRLF worktree line endings. `scripts/verify_repository.py` hashed raw worktree bytes, so unchanged design source produced a different SHA-256 and CI reported false `brand contract drift`.

Example observed for `vib_validation_app/tokens.py`:

- approved canonical LF SHA-256: `cdae402dccdb8e916f274ea5fa0b8ec1a6505fab6043462d35af8a93e1468a02`
- Windows CRLF worktree SHA-256: `f265ad4b573454d213953f21ea572626c0430e07be2bc439c8734116d70111f7`

The GitHub blob itself remained the approved LF content; the mismatch was caused only by checkout materialization.

## Fix

1. Frozen text-contract hashing now canonicalizes `CRLF` to `LF` before SHA-256 calculation.
2. `.gitattributes` pins Python, JSON, SVG, Markdown, TOML, YAML, CFF and YGIT text files to LF checkout.
3. Binary assets and release artifacts are explicitly marked binary.
4. The Windows CI job sets `PYTHONPATH` to `${{ github.workspace }}\src` so source-layout tests can import `vibrapilot` without installing the package.

## Scope

CI/repository verification only. No application runtime, browser automation, workflow, selector, settings, licensing or UI behavior changed. Version remains `1.0.6.1`.
