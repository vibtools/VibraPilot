# VibraPilot v1.0.6.9 — Workflow Inputs forensic verification/fix

This release verifies the approved v1.0.6.8 `VP-WORKFLOW-INPUTS-001` implementation against GitHub commit `82fc678fe4d3e8aab9c11ff3e54cf4455e0d3203` and changes only two Workflow Inputs persistence-error paths.

## Confirmed v1.0.6.8 implementation

- A real top-level **Workflow Inputs** page exists after **Tasks**.
- `default_full_name`, `default_number`, `fallback_name` and `update_click_count` are removed from App Settings UI and exposed on Workflow Inputs using the same existing setting keys.
- Existing persisted values continue through the existing `SettingsManager` source of truth.
- `default_target_url` remains in App Settings.
- No fake/single-option workflow selector exists.
- `src/vibrapilot/workflow_inputs.py` remains form metadata only.
- Backend worker, selectors, task/recovery runtime, Browser Settings and Licora Secure API v2 are unchanged.

The four moved values are persisted configuration values. Because `VP-WORKFLOW-INPUTS-001` explicitly preserved backend behavior, this UI separation does not add a new browser-workflow consumer for values that the frozen backend did not already consume.

## Verified defects fixed

### Save failure rollback

In v1.0.6.8, `save_workflow_inputs()` updated `SettingsManager.data` before calling `SettingsManager.save()`. If the file write failed, the exception was shown to the user but the unsaved values remained authoritative in memory.

v1.0.6.9 snapshots the exact four pre-save values. A failed write restores that snapshot, refreshes the Workflow Inputs widgets from the restored state, and then reports the error.

### Reset failure containment

In v1.0.6.8, `reset_workflow_inputs()` replaced the four in-memory values before saving, and a write failure was not caught inside the page handler. That could leave source defaults in memory and propagate an exception through the Qt event path.

v1.0.6.9 snapshots the pre-reset values, restores them if persistence fails, refreshes the page, and surfaces the error without allowing the write exception to escape the Workflow Inputs handler.

## Scope preservation

No backend, browser, selector, SQLite, licensing, settings-key, task workflow, report, dependency or Workflow Inputs metadata change is included. Successful Save/Reset behavior is unchanged.
