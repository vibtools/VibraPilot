# v1.0.6.1 — GitHub CI Repository Hygiene Fix

Date: 2026-08-08

## Scope

CI/repository-verification maintenance only. Runtime application behavior is unchanged.

## Root causes

1. The public GitHub repository intentionally ignores `project/`, but `scripts/verify_repository.py` and `tests/test_backend_contract.py` still required the private source baseline from that directory.
2. The verifier's required-file list also required private `project/` documents that cannot exist in a clean public checkout.
3. The public docs index linked to private `project/` files, creating broken GitHub documentation links.
4. CI still used `actions/checkout@v4` and `actions/setup-python@v5`, which target deprecated Node 20 and generated runner warnings.
5. Stale pre-rebrand source/launcher paths were still present in the baseline and conflict with the existing VibraPilot branding contract tests and repository hygiene checks.

## Fix

- Added a public machine-readable backend parity contract at `config/verification/backend_v1.0.6_contract.json`.
- CI backend parity no longer requires private `project/` content.
- Local developer verification still cross-checks the public contract against the private baseline when `project/` is present.
- Removed `project/` paths from public required-file checks.
- Updated backend contract tests to use the public verification contract.
- Upgraded official GitHub Actions to `actions/checkout@v5` and `actions/setup-python@v6`, both Node 24-native.
- Removed stale pre-rebrand source package and launcher from the clean public project state.
- Updated public documentation so `docs/` contains public verification guidance while `project/` remains private and gitignored.

## Preserved

- VibraPilot application version remains `1.0.6.1`.
- No browser automation workflow, selector, task behavior, licensing behavior, settings behavior, dashboard/report/log behavior or runtime UI behavior changed.
