# VibraPilot v1.0.6.8 — Workflow Inputs separation

`VP-WORKFLOW-INPUTS-001` separates workflow/form values from application settings without changing their persisted keys or backend behavior.

## Approved UI ownership change

A new top-level **Workflow Inputs** page is placed after **Tasks**. Its **Default Form Inputs** section owns the existing settings-backed fields:

- `default_full_name`
- `default_number`
- `fallback_name`
- `update_click_count`

These keys are not renamed, migrated or duplicated. Existing values already stored in `settings.json` continue to load through the existing `SettingsManager` source of truth.

## Preserved boundaries

`default_target_url` remains in **App Settings**. Browser Settings, task processing, `AutomationWorker`, selectors, Licora Secure API v2, reporting, recovery and SQLite runtime persistence are unchanged.

The page intentionally has no workflow selector while only one real workflow is present. This avoids a demo/single-option control. The new `src/vibrapilot/workflow_inputs.py` module contains form metadata only and no Playwright/browser/task logic.

## Reset behavior

**Reset Workflow Inputs** resets only the four workflow keys to their existing source defaults. App Settings and Browser Settings are preserved.
