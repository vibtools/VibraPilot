# v1.0.6.10 — License Login Durability and Recovery Fix

## Baseline and scope

This update is anchored to the exact pushed **VibraPilot v1.0.6.9** GitHub commit `cd6ec96736626256daeed1d36775d21e90abf7ee` and clean v1.0.6.9 baseline archive SHA-256 `fe5ebed39608735dc72674a7342cb5f68afa3831afb94b8b944d210464d27805`.

The runtime scope is limited to `LicenseManager` state/session behavior in `src/vibrapilot/backend.py` and the background license recheck method in `src/vibrapilot/qt_app.py`. `src/vibrapilot/licensing_v2.py`, the pinned RSA public key, API paths, ActivationPage visual contract, browser/task/workflow/report behavior and Licora server source are frozen.

## Verified root causes

1. **Install-relative device identity caused `DEVICE_KEY_MISMATCH`.** v1.0.6.9 stored the DPAPI-protected P-256 key in project/install-relative `AppData/license.json` while `device_id()` was deterministic. A clean/new folder could therefore generate a new P-256 key but send the same historical device ID. Production Licora binds `license + app + device_id` to the registered public-key fingerprint and rejects a different fingerprint with `DEVICE_KEY_MISMATCH`.
2. **Client logout and server revoke semantics did not support same-device re-login.** VibraPilot logout called `/api/v2/deactivate.php`; current Licora deactivation permanently revokes the v2 credential and marks the corresponding device inactive. Re-activating the same device ID is rejected as `DEVICE_REVOKED`.
3. **Background recheck treated transient transport failures as authoritative.** A network/rate-limit/invalid-response failure returned `False`, and the UI unconditionally called logout even when the already verified access token was still locally valid.
4. **Logout deactivation could race a new activation.** Remote deactivation ran asynchronously. Without ordering, a new login could succeed before the stale logout request reached the server, after which that request could revoke the fresh session/device.

## Fixes

- Default Windows license/session state now lives in `%LOCALAPPDATA%\Vib Tools\VibraPilot` unless `VIB_TOOLS_DATA_DIR` is explicitly configured.
- Historical install-relative `AppData/license.json` is copied once into durable storage when no durable session exists.
- `device_identity.json` separately DPAPI-protects the P-256 private key, fingerprint and stable client device ID. Session-cache corruption no longer discards a valid durable device identity.
- `DEVICE_KEY_MISMATCH` and `DEVICE_REVOKED` receive one bounded, restart-safe device-ID recovery attempt using the existing P-256 key. The new ID is persisted before transmission.
- If the old active registration already fills the license device limit, recovery stops with an explicit stale-device cleanup message; the client does not loop or bypass the server limit.
- Confirmed remote logout deactivation rotates the now-revoked client device ID before the next login. Ambiguous/failed deactivation preserves the old ID so the next activation can resolve server state safely.
- New validation cannot overtake pending remote logout deactivation. The pending-logout state is checked again while validation and state locks are held, closing the post-wait race window.
- Background recheck keeps a session only when the validation failure is classified transient **and** the current access token still verifies locally as unexpired. Expired/invalid local authorization remains fail-closed.
- Server error text is mapped to concise, stable-code activation messages without changing the ActivationPage visual contract.

## Server boundary

No Licora server file is modified by this patch. A stale active registration that consumes the final allowed device slot cannot be securely deleted/rebound by the desktop client under the current API v2 contract when the old private key/session is unavailable. That specific condition requires Licora administrator device cleanup; the desktop client reports it explicitly.
