The only failure was the second test runner, standard-library `unittest`, in:

`TaskRuntimeStoreTest.test_four_worker_threads_persist_independent_results_without_cross_run_leak`

## Root cause

The runtime store already serializes in-process SQLite writers and the hot path already persists item/result/progress in one durable transaction. The failing test was therefore not exercising a missing Phase-01 browser behavior.

The test used a fixed `thread.join(timeout=15)` limit. On the hosted Windows runner, four concurrent test writers performing FULL-synchronous WAL commits exceeded that 15-second wall-clock threshold. The test immediately asserted while a writer was still alive. When the temporary directory then exited, Windows correctly refused to unlink `store.sqlite3` while that writer still held the file, producing the secondary `WinError 32`.

The same test had passed minutes earlier inside the full pytest suite on the same job. This confirms a timing-sensitive verification threshold rather than deterministic data corruption or cross-run leakage.

## Correction

v1.0.6.13 changes **no production runtime source file**.

The concurrency test now:

- uses a shared bounded **60-second** deadlock guard,
- waits against one common deadline rather than 15 seconds per assumption,
- treats the test as a correctness/isolation test rather than a storage throughput SLA,
- uses cleanup-tolerant temporary-directory semantics so a primary timeout failure is not obscured by a secondary Windows file-deletion exception.

A new scope contract freezes:

- `src/vibrapilot/backend.py`
- `src/vibrapilot/qt_app.py`
- `src/vibrapilot/task_runtime_store.py`
- licensing/client runtime
- Workflow Inputs
- data I/O
- focus manager
- Browser Settings defaults
- the v1.0.6.12 Phase-01 scope contract

## Packaging finding

The uploaded v1.0.6.12 archive contains runtime/cache/private-development material including `AppData`, `Logs`, `.pytest_cache`, Python bytecode caches and the private `project/` workspace.

That archive is accepted as the forensic input baseline because the user explicitly froze it, but it is **not** a clean public source archive.

Public source/release artifacts must pass:

```cmd
python scripts/verify_source_archive.py <source-zip>
```

and exclude private/runtime/cache paths.
