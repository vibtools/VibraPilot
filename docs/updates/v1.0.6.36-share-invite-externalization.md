# v1.0.6.36 — Share Invite Workflow Externalization

## Scope

This release changes only the workflow hosting boundary required to remove Share Invite from VibraPilot Core. The Core catalog has zero built-in workflows, a fresh application can remain in a valid zero-active-workflow state, and Share Invite is distributed separately as a trusted Plugin API 1 `.vpworkflow` package.

## Behavior preserved

The external Share Invite workflow keeps the same `share_invite` identity, selectors, authenticated Test Mode gate, pre-Send Test Mode check, Send-click accounting, retry/backoff behavior, SecurityChallenge/manual-review handling, duplicate-send protection, result confirmation and audited TXT/CSV/XLSX/XLS data loading semantics from v1.0.6.35.

Existing schema-v1 `share_invite` active state is upgraded to workflow-state schema v2 without quarantine. If the package is not installed yet, the identity and canonical per-workflow values are preserved and the UI reports that the matching trusted package is required.

## Compatibility

Plugin API remains version 1. Existing workflows using the original optional `load_task_items` hook continue to work. `load_task_data` and runtime `process_item` are optional backward-compatible extensions; they are used to move Share Invite-specific audit metadata and orchestration out of Core.

## Explicitly unchanged

Google Chrome runtime/install/Authenticode, Playwright/browser profiles/diagnostics, licensing/Licora, TaskRuntime database schema, workspace schema, reports, downloads/uploads, dependencies, CI, build/Nuitka/WiX, workflow URL loading, workflow update/replace and workflow uninstall are outside this release.
