# v1.0.6.22 — PR-05 Master Workflow Gate Integration

## Scope

PR-05 inserts one fail-closed execution gate between `AutomationWorker` and the active source-controlled built-in workflow. The active identity is in-memory only and defaults to `share_invite` for the current application. No persistence, switching, activation UI, restart behavior or external plugin loading is introduced.

## Implementation

- `WorkflowRuntime` exposes generic `session_ready`, `ensure_session`, `execute_item` and `prepare_retry` operations.
- `WorkflowManager` owns an immutable in-memory `active_workflow_id`, validates it against the built-in registry and resolves only source-controlled runtime factories.
- Missing/unknown workflow IDs, absent runtime factories and manifest/runtime mismatches fail closed.
- `ShareInviteWorkflow` adds generic adapters that call the existing verified Share Invite methods.
- `AutomationWorker` owns the Master Workflow Gate and routes its existing session/execution/retry compatibility boundaries through the active runtime.

## Safety Preservation

`process_item`, `process_batch`, `_register_send_click_attempt`, report semantics, browser lifecycle, pause/resume/stop, task/workspace persistence, selectors, Test Mode, retry/backoff, Send limits, security challenge handling and uncertain-Send/manual-review protection remain unchanged.

## Deferred

PR-06 will own active workflow persistence and safe switching/restart. Workflow showcase UI and dynamic Workflow Inputs remain later phases. CAPTCHA/stealth work remains deferred.
