# VibraPilot v1.0.6.14 — Managed Persistent Browser + Closed Task Recovery

## Scope

This candidate implements the approved `VP-MANAGED-PERSISTENT-BROWSER-001` plan plus the explicit `VP-CLOSED-TASK-RECOVERY-001` amendment from the verified v1.0.6.13 baseline.

## Managed persistent browser

- Persistent Playwright browser context is enabled by default.
- Blank profile roots resolve to the VibraPilot-managed durable Windows profile root; explicit `VIB_TOOLS_DATA_DIR` is preserved.
- Dedicated profiles remain mapped deterministically from Task slot ID as `slot_<id>`.
- The user's normal Google Chrome `User Data` tree is rejected at settings-save and backend launch boundaries.
- Exact legacy default settings are promoted to the new managed default without overwriting customized profile settings.
- A legacy VibraPilot-managed profile is migrated only when the new target profile does not already exist; no profile merge/delete is performed.
- Controlled persistent-context recycling is marked as an internal transition and login state is re-verified after relaunch.
- `restore_previous_session` remains false.

## Closed Task recovery

- **Close Task** persists the current Task snapshot before removing the Task card.
- Closed state is recorded in the existing `runs.task_status` field; schema version 1 and all existing tables/columns remain unchanged.
- **Open Closed Tasks** restores all deliberately closed Tasks that do not conflict with an already-open slot.
- Reopen preserves original slot ID and run ID, recipient items, Target URL, current index, counts, send-limit usage, manual-review state and result continuity.
- Browser remains Closed and login Not Verified after restore; user must explicitly open the browser and start/resume automation.
- Closing a Task never deletes its managed browser profile.

## Preserved

Phase-01 browser lifecycle/geometry, Razorpay Share Invite workflow/selectors, Test Mode/security behavior, retry/backoff, licensing, Workflow Inputs, reporting, TaskRuntimeStore schema and dependencies remain preserved. No download/upload/extension/stealth/CAPTCHA feature is added.

## Acceptance boundary

Source regression can verify path resolution, schema preservation, state continuity and lifecycle integration. Real Chrome cookie/localStorage/history persistence, profile isolation across actual Chrome sessions, manual-close behavior and app-restart continuity remain mandatory Windows acceptance items before v1.0.6.14 becomes the next Official Baseline.
