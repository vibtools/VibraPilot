# VibraPilot v1.0.6.1

Release date: 2026-08-07

## Scope

Browser Settings / Playwright runtime production hardening only. The existing built-in site-specific workflow and unrelated application pages are preserved.

## Forensic findings

The previous Browser Settings master page had broad source-level wiring, but several controls did not fully match the Chromium process because Playwright supplies its own default launch arguments. The audit compared UI keys, persisted defaults, `AutomationWorker` consumers and the project-pinned Playwright 1.61 Chromium launch/context API contract.

### Corrected controls

- **Allow Popups**: Playwright adds `--disable-popup-blocking` by default. The application now ignores that Playwright default when the setting is OFF, restoring normal Chromium popup blocking, and explicitly permits popups when ON.
- **Background Throttling Enabled**: Playwright adds three background-throttling-disabling defaults. When the setting is ON those defaults are ignored; when OFF the disabling flags remain authoritative.
- **Load Chromium Extensions**: Playwright's default `--disable-extensions` is ignored only when extension loading is explicitly enabled, and the full Playwright `chromium` channel is selected for bundled extension sessions so headless mode does not fall back to the separate headless shell.
- **DevTools Auto Open**: Playwright 1.61 no longer exposes the previous `devtools` launch keyword. The setting now maps to Chromium's `--auto-open-devtools-for-tabs` command-line switch.
- **Audio Enabled**: Playwright headless Chromium adds `--mute-audio` by default. The setting now filters that default when audio is enabled and explicitly mutes when disabled, so the UI value remains authoritative in both headed and headless mode.
- **Allow Bundled Chromium Fallback**: persistent Chrome-channel launch now receives the same fallback behavior as ephemeral launch.
- **Restore Previous Browser Session**: validated as persistent-profile-only.
- **Conditional validation**: session restoration now also requires profile persistence between runs, and X/Y window-position overrides must be configured as a valid pair.

### Removed controls/configuration

- Duplicate **Hardware Acceleration Enabled** alias. Its previous effective state is migrated into **GPU / Hardware Acceleration Enabled**.
- Hidden legacy `disable_image_font_media_loading` runtime key after migration into the explicit Block Images/Fonts/Media controls.
- Informational/read-only cards from the Browser Settings UI. Non-settings are documented, not displayed as controls.

## Persistence and UI truthfulness

Browser Settings are parsed, validated and saved through `SettingsManager`. After successful save/reset, controls are populated again from `SettingsManager`, so normalized JSON/enums/booleans displayed by the UI match the backend persistence state. Active workers still receive the saved settings snapshot; launch/context-only options take effect at their corresponding browser lifecycle boundary.

## Unsupported policy features

Chrome policy/profile features without a stable general Playwright/Chromium configuration contract are intentionally not represented by demo switches. Raw supported needs can be handled through persistent profiles, Additional Chromium Arguments, Browser Environment Variables and Chrome/Blink feature lists.

## Compatibility

The v1.0.6 baseline `AutomationWorker` method inventory remains 54 methods. No existing site-specific selector or send-workflow change is part of this release.
