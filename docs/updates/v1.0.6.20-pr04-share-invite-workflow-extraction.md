## Objective

Encapsulate the existing verified Share Invite workflow behind the PR-03 built-in workflow framework without redesigning its behavior.

## Implemented

- Added `src/vibrapilot/workflow/share_invite/` with a validated source-controlled manifest, exact existing VibraPilot logo and extracted runtime implementation.
- Added the Share Invite manifest to an explicit deterministic built-in registry factory. The default `WorkflowManager()` remains empty; no active workflow or switching state is introduced.
- Added a minimal `WorkflowRuntime` protocol required by the extracted workflow.
- Replaced Share Invite-specific `AutomationWorker` method bodies with thin compatibility delegation to `ShareInviteWorkflow`.
- Updated repository verification and tests only where the approved extraction moved browser-setting consumers from `backend.py` to the new workflow module.

## Behavioral parity / safety

The following remain frozen by source/AST/parity contracts:

- `AutomationWorker.process_item()` retry/state machine;
- `_register_send_click_attempt()` durable pre-Send manual-review marker;
- `process_batch()` and report-row behavior;
- Share Invite selector values and priority;
- existing exception identity/inheritance;
- Test Mode/session enforcement and email re-verification immediately before Send;
- pre-Send retry behavior;
- post-Send uncertain outcome → manual review → no automatic duplicate retry;
- SecurityChallenge behavior;
- success/rejection/result string semantics.

## Explicitly unchanged
