# v1.0.6.23 — PR-06 Workflow State Persistence and Atomic Switch/Restart

## Scope

PR-06 persists exactly one active built-in workflow and introduces the application-level atomic switch/restart service required by later Workflow UI. Production still registers only `share_invite`.

## State

`AppData/workflow_state.json` uses schema version 1. If the file is absent, existing users migrate once to `share_invite`. Existing corrupt, unsupported or unknown state is quarantined/fail-closed and never silently converted to Share Invite.

## Switch transaction

A real different-workflow switch validates the target, blocks while Tasks are processing or require manual review, requires user confirmation, settles idle workers, stages rollback copies, clears only approved workflow-scoped live state/input values, atomically replaces workflow state as the commit point, and restarts only after commit. PREPARED interrupted transactions roll back; COMMITTED transactions preserve the new workflow and clean stale staging.

## Preserve boundary

License/device identity, global settings other than the four workflow-input keys, Browser Settings/profiles/storage, Downloads/extensions, exported Reports, FailedData, Logs, user source files, window/page state and source-controlled workflow definitions are preserved.

## Deferred

PR-07 owns Workflow Showcase UI. PR-08 owns dynamic/per-workflow inputs. PR-09 owns workflow-aware data/report schemas.
