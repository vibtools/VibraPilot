## Implemented scope

### Durable downloads
- Existing `accept_downloads` and `downloads_path` settings remain authoritative.
- Blank `downloads_path` resolves to a durable VibraPilot-managed per-Task directory.
- Explicit download paths preserve baseline semantics.
- Page download events are captured and copied durably with `Download.save_as()`.
- Website filenames are sanitized and same-name files receive non-destructive numeric suffixes.
- Task cards expose **Downloads** to open the effective directory.
- Start/saved/failure lifecycle information is surfaced through Live Logs.

### Browser file chooser uploads
- VibraPilot reacts only after the webpage triggers a file chooser.
- The operator must explicitly choose a file, multiple files, or directory as requested by the page.
- An opaque request ID ties the UI response to the exact pending chooser.
- Pending choosers are invalidated on page/context/browser/Task lifecycle loss.
- Selected local upload paths are not persisted to settings, workspace state, TaskRuntimeStore or reports.

### Unpacked extensions
- Existing extension settings are retained.
- Configured directories are normalized/deduplicated.
- Each enabled extension directory must exist and contain a `manifest.json` JSON object.
- Validation occurs at Browser Settings save and browser launch boundaries.
- Persistent Chromium-compatible side-loading remains the supported model; Chrome Web Store/CRX/ZIP installation is not added.

## Explicit non-goals

No automatic file upload, saved upload replay, workflow-defined upload action, download-history database/page, Chrome Web Store automation, extension marketplace/updater, CAPTCHA bypass, stealth/fingerprint change, database schema change, settings-key change or new application page is included.
