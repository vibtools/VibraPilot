## Corrective scope

v1.0.6.40 does not add Phase 2 functionality. It closes only defects or exact-plan mismatches found while auditing the already-implemented v1.0.6.39 Phase 1 runtime reliability work.

### Corrected

1. The Windows system-sleep guard is now acquired inside a guaranteed `process_batch()` cleanup boundary and released before fallible final persistence/UI work, preventing an early worker failure from stranding the process-level power request.
2. Context recycle can explicitly re-probe a session-required workflow even while `processing_event` is set. Both persistent and non-persistent recycle paths use that forced probe.
3. A failed required-session re-probe after recycle now blocks before the next workflow item rather than continuing automation with an unverified session.
4. The deterministic page-origin helper now treats malformed HTTP/HTTPS port values as invalid input instead of allowing `urlparse().port` to raise `ValueError` into the browser worker.
5. Dashboard session readiness uses the exact `Login Verification` display label while preserving the existing internal metric key.
6. Repository verification now checks the actual Windows `PowerRequestSystemRequired` numeric enum (`0`) instead of accepting a docstring-only text marker as evidence.

## Frozen

No change is authorized to workflow Update/Replace/Unload, restart-free workflow switching, per-Task workflow identity, true different-workflow concurrency, Plugin API, workflow state/schema, external workflow business logic, licensing, Task/workspace/report schemas, Chrome installer, dependencies, CI workflows or portable-release architecture.

Because v1.0.6.40 is consumed by this Phase 1 forensic closure, the planned Phase 2 implementation version is moved to **v1.0.6.41** without starting Phase 2.
