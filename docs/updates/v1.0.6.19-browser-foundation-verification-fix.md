## v1.0.6.18 diagnostics defects corrected

### Runtime dependency compatibility was captured but not classified

v1.0.6.18 persisted the installed Playwright version, but did not state whether it matched the project requirement. v1.0.6.19 records:

- expected version;
- actual version;
- compatibility boolean;

and emits a non-fatal Live Logs warning when they differ.

The browser still launches; the diagnostic does not silently change browser policy.

### Fallback diagnostic text was persisted raw

The v1.0.6.18 record stored `fallback_reason` directly from an exception string. Because browser-launch exception text can contain command-line or proxy detail, v1.0.6.19 sanitizes the persisted/logged fallback diagnostic text.

### Nested launch evidence lost JSON scalar types

The generic v1.0.6.18 launch-kwargs sanitizer converted nested dictionary values to strings. For example, the captured `viewport.width` and `viewport.height` became string values. v1.0.6.19 preserves JSON numeric/boolean types while retaining redaction.

## New verification tooling

`scripts/diagnostics/verify_browser_foundation_evidence.py`

This tool reads a `slot_N_latest.json` record and reports:

- actual engine/product/executable;
- profile path;
- fallback state;
- Sandbox requested state;
- presence of `--no-sandbox`;
- runtime Playwright version;
- required Playwright version.

The tool validates evidence only. It does not launch or configure a browser.
