# v1.0.6.12 — VP-BROWSER-UI-LIFECYCLE-001

## Baseline and scope

Baseline: VibraPilot v1.0.6.11 archive SHA-256 `9ecb7cd66f24832c3555d219a6f8aaf47358877dd417eeb703b5a755964fc90a`, GitHub commit `8670415b1df221ebeeb7d8f3fba4f991a91d43ec`.

Approved runtime files:

- `src/vibrapilot/backend.py`
- `src/vibrapilot/qt_app.py`

Phase-02 managed-persistent-browser work is explicitly excluded.

## Root causes addressed

1. Non-persistent Task browser readiness previously depended on the browser connection while the visible active page could already be closed.
2. Page/context/browser close events were not mapped into a complete Task lifecycle state bridge.
3. The Task toolbar used a static `Open Browser` action even when the browser was already open; the same action then requested focus.
4. Controlled browser cleanup existed but there was no dedicated browser-only Close action distinct from `Close Task`.
5. Login and Dashboard readiness inherited stale browser state.
6. The compact centered activation window expanded to workspace size without a new safe center/clamp step.

## Implementation

### Worker lifecycle truth

`AutomationWorker` now owns a deterministic `CLOSED / OPENING / OPEN / CLOSING` lifecycle. The Qt thread consumes thread-safe readiness events rather than calling Playwright wrappers directly. The worker attaches idempotent handlers for:

- active page close,
- BrowserContext close,
- Browser disconnect.

A live replacement page can remain available after the active page closes, but login verification is cleared and must be re-established. When no usable page/context/browser remains, browser and login readiness are cleared.

The existing `auto_restart_browser_on_crash` policy remains authoritative. With restart disabled, an external/manual close keeps the Task for reopening instead of deleting it.

### Task UI action

The existing primary browser action is stateful:

- `Closed` → **Open Browser**
- `Opening` → **Opening...** (disabled)
- `Open` → **Close Browser**
- `Closing` → **Closing...** (disabled)

`Close Browser` requests controlled worker shutdown but leaves the Task card, URL, loaded data, counts and runtime/recovery state intact. `Close Task` remains separate.

### Workspace geometry

After the live workspace shell is built, the window is resized to the configured default where possible, clamped to the current screen's available geometry and centered. No geometry persistence or new setting is introduced.
