# VibraPilot v1.0.6.4 — Phase-02-Step-002 Forensic Verification/Fix

**Date:** 2026-08-08  
**Official baseline:** user-supplied `VibraPilot v1.0.6.3.zip`  
**Baseline SHA-256:** `eec7ed0c5579f4a997c513f78c24ac93b1d814e6d6f8cb06c37d5fb064602078`  
**Scope:** Phase-02-Step-002 licensing/session verification fixes, verification coverage, release hygiene and synchronized release metadata/documentation only

## Findings corrected

1. **Device key continuity:** v1.0.6.3 cleared its P-256 device private key on logout/license switch and did not persist a newly generated key until after activation success. An ambiguous activation/deactivation outcome could therefore leave Licora bound to a public key the restarted client no longer possessed. v1.0.6.4 persists the device key before the first activation request and retains it across logout/license switching.
2. **Refresh ambiguity durability:** v1.0.6.3 cleared an ambiguous refresh token only in memory before re-activation. A crash/restart could reload the old one-time refresh credential from disk. v1.0.6.4 atomically persists token invalidation before recovery activation.
3. **UI/network lock coupling:** v1.0.6.3 kept the license state lock across remote HTTP validation, allowing dashboard license reads to block behind network I/O. v1.0.6.4 separates the validation lock from the short state lock and guards stale commits with a state generation.
4. **Startup restore:** v1.0.6.3 only accepted an already-valid local access token at startup; expired-token or legacy-cache restoration was not automatically attempted. v1.0.6.4 uses the existing ActivationPage shell to perform a background secure restore without redesigning the UI.
5. **Expired-token periodic recheck:** v1.0.6.3 gated periodic validation on `is_activated()`, so an expired access token could stop the refresh path. v1.0.6.4 rechecks whenever a license is present.
6. **Repeated token verification:** the dashboard could repeatedly parse the RSA key and reverify an unchanged token. v1.0.6.4 caches already verified access-token state until expiry.
7. **Atomic durability:** license-cache writes now flush and fsync the temporary file before atomic replacement.
8. **Release-package hygiene:** the supplied v1.0.6.3 archive contained gitignored runtime/private/cache paths, including a DPAPI-protected runtime license cache. v1.0.6.4 official packages exclude those paths and verification encodes the exclusion boundary. No private values are copied into release output.
9. **Verification command mismatch:** pytest now receives `src` through project configuration, matching the documented plain `python -m pytest -q` command.
10. **Unittest shell/import mismatch:** the standard-library suite previously depended on an external `PYTHONPATH`, while the documented setup used PowerShell syntax that fails in Windows Command Prompt. The affected unittest modules now bootstrap the repository `src` layout themselves, so `python -m unittest discover -s tests -p "test_*.py" -v` works directly in either shell.

## Scope preservation

`src/vibrapilot/licensing_v2.py`, AppConfig public licensing data, automation/browser/task/report/safety logic, selectors, `ActivationPage`, Browser Settings and the frozen Vib Tools UI foundation are outside the approved runtime fix surface. The original Phase-02 AST freeze remains active and a second SHA-256 file-scope contract protects operational files byte-for-byte against the uploaded v1.0.6.3 baseline.

## Release boundary

The official v1.0.6.4 baseline and replace-ready delta must not include runtime/private/cache data. The following top-level paths are forbidden release inputs: `AppData/`, `FailedData/`, `Reports/`, `Logs/`, `project/`, `__pycache__/`, `.pytest_cache/`.
