# v1.0.6.31 — Chrome-Only Runtime Foundation

## Scope

Phase 1 changes only the browser runtime foundation.

### Implemented

- Playwright remains the automation layer.
- Browser launch is fixed to `channel="chrome"`.
- Chromium retry/fallback launch paths are removed.
- Persistent-profile failure may still use the existing ephemeral-context policy, but the browser engine remains Google Chrome.
- Arbitrary `browser_executable_path` runtime authority is removed.
- VibraPilot unpacked-extension Chromium launch mode is disabled; normal Chrome extension service remains enabled.
- `chromium_sandbox=True` is mandatory.
- `http_cache_enabled=true` is the source/default migration value.
- A versioned settings migration prevents stale settings from bypassing mandatory Chrome/security policy.
- `chrome_runtime.py` discovers and validates Windows Google Chrome candidates for runtime status/future prerequisite UX.
- Browser Settings now show Chrome-only policy/status read-only information rather than editable engine/fallback/security choices.
- Browser diagnostics record Chrome-only policy compliance/violation.
- Policy-conflicting advanced browser arguments such as sandbox-disable, unpacked-extension side-loading and alternate user-data-dir overrides are rejected before launch.

### Preserved

Managed persistent profiles, Task isolation, workflows, licensing, reports, persistence, downloads/uploads, browser lifecycle behavior and public CI/build files remain outside this functional change.

### Deferred

Chrome download/install UX is a separate future phase/version and is not part of v1.0.6.31. Build-system removal of bundled Chromium assets and final EXE/MSI build are later separate work.
