# v1.0.6.11 — Qt Focus Lifecycle Fix

## Scope

Plan `VP-QT-FOCUS-LIFECYCLE-001` is anchored to VibraPilot v1.0.6.10, GitHub commit `d712a9d04fa62e5e3a0df9c00a99c1315052bd05`. The only approved runtime file is `vib_validation_app/focus_manager.py`.

## Confirmed Windows defect

A focused PySide6 `QLineEdit` could be destroyed when the application replaced a page or central widget while `KeyboardFocusRingManager` still retained the Python wrapper. On a later focus event, the manager attempted `setProperty()`/style operations on that wrapper and Shiboken raised `RuntimeError: Internal C++ object ... already deleted`. The same lifetime family existed for the 180 ms delayed keyboard-focus tooltip callback.

## Correction

- Use Shiboken's existing `isValid()` facility to confirm the underlying C++ QWidget is still alive before focus property/style or tooltip operations.
- Clear the retained focused-widget reference when Qt emits `Destroy` or `DeferredDelete`.
- Ignore only the exact deleted-object `RuntimeError` race if the wrapper becomes invalid between a validity probe and the Qt call; a `RuntimeError` on a still-live widget is re-raised.
- Preserve the existing `keyboardFocus` dynamic property, `true`/`false` values, style unpolish/polish/update sequence, 180 ms tooltip timing, keyboard modality and mouse modality behavior.

## Preserved boundaries

No change is made to `src/vibrapilot/backend.py`, `src/vibrapilot/qt_app.py`, Licora API v2, ActivationPage, Browser Settings, Tasks, Workflow Inputs, Reports, task persistence, selectors, browser automation, settings defaults or dependencies. Frozen visual tokens and all other Vib Tools design-system modules remain byte-identical to v1.0.6.10.

## Platform acceptance

The automated source suite includes PySide6 runtime regression tests when PySide6/Shiboken6 are installed. Final production acceptance still requires Windows 10/11 Python 3.12 `python run.py` verification through Activation→Workspace and Workspace→Activation/logout transitions with zero `libshiboken`/`QObject::eventFilter` traceback output.
