# v1.0.6.1 — GitHub CI deterministic backend-contract fix

Date: 2026-08-08

## Scope

GitHub CI and public repository verification only. No runtime application source or workflow behavior is changed.

## Failure

The Windows GitHub Actions Python 3.12 job reached verifier step `[4/8] Core backend class/method parity` and reported:

```text
VERIFY FAILED: backend implementation drift in core class TaskItem
```

The checked-in `TaskItem` implementation was not actually different from the validated private v1.0.6 baseline.

## Root cause

The public backend contract stored SHA-256 values of raw `ast.dump(node, include_attributes=False)` output. Raw AST dump text is not a portable serialization contract across CPython minor versions. Python versions can expose new optional fields, including empty `type_params` fields on class/function nodes, causing different dump text for semantically identical source.

## Resolution

- Introduced `canonical-semantic-ast-v2`.
- AST nodes are serialized as semantic node/field values.
- `None`, empty-list and empty-tuple optional fields are omitted.
- Frozen class/helper hashes were regenerated from the private source baseline.
- The machine contract records the hash algorithm and the verifier rejects an incompatible contract explicitly.
- Contract tests verify all frozen production hashes using the canonical algorithm.
- The optional local private-baseline check now validates canonical implementation hashes as well as method inventories.

## GitHub Actions maintenance

The workflow now uses:

```yaml
actions/checkout@v5
actions/setup-python@v6
```

Both are Node 24-native action generations, replacing the older actions responsible for the Node 20 deprecation warning.

## Repository boundary

- Public documentation and verification notes: `docs/`
- Private development/source-baseline material: gitignored `project/`
- Public CI must not require `project/`.

## Version

Application version remains `1.0.6.1`.
