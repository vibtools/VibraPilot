## Findings

- **[CONFIRMED] `DEVICE_KEY_MISMATCH` client-state root cause:** v1.0.6.9 tied the private device key to an install/project-local cache while reusing a deterministic device ID. Licora rejects a new fingerprint for an existing `license + app + device_id` credential.
- **[CONFIRMED] logout/re-login mismatch:** current Licora `/api/v2/deactivate.php` permanently revokes the credential/device ID; v1.0.6.9 retained and reused that ID after logout.
- **[CONFIRMED] transient recheck logout:** the previous background recheck called `logout()` for any failed `validate()`, including non-authoritative network/rate-limit/server-response failures.
- **[CONFIRMED] logout ordering race:** asynchronous deactivation was not ordered against a new activation.
- **[CONFIRMED] no fake/demo licensing protocol:** the desktop client uses real P-256 request proof, RS256 token verification, rotating refresh tokens and production v2 endpoints. No API v1 shared/master key is active.

## v1.0.6.10 corrections

- Durable per-user Windows license state and separate DPAPI-protected device identity.
- Legacy protected-cache migration without exposing plaintext secrets.
- Bounded `DEVICE_KEY_MISMATCH`/`DEVICE_REVOKED` recovery with pre-request persistence.
- Explicit stale-device/device-limit boundary instead of retry loops.
- Serialized logout deactivation and re-login, including a second pending-logout check under validation/state locks.
- Transient background recheck preservation only while a locally verified token remains valid.
- Concise stable-code activation error text.

## Security invariants

- Licora API v1 shared/master client credential: forbidden.
- Server RSA private signing key in client: forbidden.
- P-256 private key sent to server: forbidden.
- HTTPS certificate verification: retained.
- Access-token RS256 verification: retained.
- Refresh-token blind retry after ambiguous rotation: forbidden.
- Device-limit bypass: not implemented.
- Automatic administrator/server-record deletion: not implemented.

## Verification gate

The release must pass repository verifier, compileall, pytest, unittest, delta replacement simulation and clean source-archive verification. Windows live activation remains a platform gate and must prove: old mismatched registration recovery, restart restore, background recheck, logout, and same-license re-login.

## Platform/live boundary

The forensic environment is not the supported Windows/Python 3.12 GUI deployment, and no real production license key is used by automated tests. The final Windows gate must therefore exercise the actual Licora account without exposing the key in source/log output. In particular, verify that a previously mismatched device can activate (or receives the explicit stale-device-limit action), restart restores the session, logout completes, and the same license can activate again.
