# V1.0.6.7 Windows SQLite concurrency verification

## Reported failure

Windows 10 / Python 3.12 verification passed repository checks but failed the four-worker `TaskRuntimeStore` persistence test because at least one writer thread remained alive after 15 seconds. Cleanup then failed with `PermissionError: [WinError 32]` on `store.sqlite3`.

## Root cause

Four threads generated 1,200 independent write transactions for 400 recipients. SQLite WAL has a single writer, and the 30-second SQLite busy timeout allowed Windows writer contention to outlive the test's 15-second worker join. The file-handle error was secondary: a writer thread was still active when the temporary directory cleanup began.

## Verification target

The correction must preserve crash durability and recipient isolation while reducing writer-lock acquisition frequency. The worker hot path therefore uses one atomic item/result/progress transaction, protected by a process-local re-entrant write lock before SQLite's writer lock.
