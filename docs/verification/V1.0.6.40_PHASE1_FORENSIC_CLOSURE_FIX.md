# v1.0.6.40 Phase 1 Forensic Closure Verification

## Classification

`v1.0.6.40` is a corrective verification/fix release over the owner-frozen v1.0.6.39 Phase 1 baseline. It does not reopen Phase 2.

## Confirmed v1.0.6.39 findings

- Power Guard cleanup was not guaranteed for all early/finalization exception paths.
- Required-session context recycle called the normal login refresher while processing, where the refresher intentionally short-circuited; therefore the claimed re-probe did not actually occur.
- Recycle did not prevent the next item from running if required-session verification remained false.
- The new target-origin parser could raise on a malformed explicit port.
- The no-session-required dashboard wording was semantically understandable but did not exactly match the approved `Login Verification` label.
- The repository verifier's `PowerRequestSystemRequired` check could be satisfied by the module docstring instead of the actual enum constant.

## Closure contract

The candidate must prove:

- guard release on setup failure and fallible finalization;
- normal login polling still suppresses probes while a Task processes;
- recycle-only forced probe can execute during processing;
- both context types use the forced probe;
- a failed required-session recycle probe blocks the next item;
- sessionless workflow behavior remains outside Core login verification;
- malformed target ports fail safe;
- dashboard session wording matches the approved UI contract;
- Windows power enum is verified structurally as numeric value `0`;
- v1.0.6.39 settings policy, `power_management.py`, workflows, licensing, persistence, dependencies and CI remain frozen.

## Release boundary

Automated source/CI verification is not a substitute for owner live Windows minimized/occluded-browser and sleep-idle acceptance. Those runtime observations must not be reported as PASS unless actually performed.
