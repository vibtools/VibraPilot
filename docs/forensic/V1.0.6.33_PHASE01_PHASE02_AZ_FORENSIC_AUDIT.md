## Confirmed finding register

### F-001 — P1 — Chrome preflight and Playwright target could diverge

**Baseline:** discovery considered App Paths registry first and skipped rejected candidates, while Playwright `channel="chrome"` uses the first accessible standard Windows channel path. A valid lower-priority/registry Chrome could therefore satisfy preflight while Playwright selected another higher-priority file.

**Fix:** runtime candidates now mirror Playwright 1.61.0 Windows channel order and the first existing target is authoritative. An invalid first target fails closed; it is never skipped in favor of a lower-priority executable.

### F-002 — P1 — Installed Chrome identity was metadata-only

**Baseline:** `ProductName=Google Chrome` was treated as sufficient identity.

**Fix:** the actual channel target must also pass Windows Authenticode trust and signer `Google LLC`.

### F-003 — P1 — MSI allowlist path accepted arbitrary prefixes

**Baseline:** same-host URLs were accepted if the path merely ended in the approved filename.

**Fix:** exact path `/dl/chrome/install/googlechromestandaloneenterprise64.msi` is mandatory, with existing HTTPS/host/authority/query/fragment restrictions retained.

### F-004 — P2 — Windows Installer 1602 was generic failure

**Fix:** 1602 maps to `installer_cancelled` and is surfaced as cancellation/warning rather than a generic installation failure.

### F-005 — P2 — Security/lifecycle stage events were droppable

**Fix:** only high-frequency download byte progress uses `put_nowait`; stage transitions use non-droppable queue backpressure.

### F-006 — P2 — Active installer dialog state could be reset

**Fix:** additional prerequisite/Open Browser requests focus the existing active dialog without calling `set_missing`; re-check is blocked during active install coordination.

### F-007 — P2 — Diagnostics could overclaim identity

**Baseline:** Chrome-shaped process paths or requested `channel="chrome"` could be considered compliant evidence.

**Fix:** only a measured process path equal to the trusted Chrome channel target is compliant. Missing process evidence is explicitly `google_chrome_channel_unverified`; mismatched captured paths are violations.

### F-008 — P3 — Current-state documentation drift

**Fix:** docs now distinguish frozen v1.0.6.32 main baseline, v1.0.6.33 hotfix candidate, Chrome-present acceptance already obtained, and missing-Chrome/UAC owner acceptance still required.

### F-009 — P3 — Source EOF hygiene

**Fix:** extra trailing blank line in `chrome_runtime.py` removed.
